# JH7110多系统间通讯设计

**JH7110 hart0**：hart0不支持S态，只能运行在M态

因此采用以下架构：
- **hart0 (M态)**: embassy_preempt RTOS
- **hart1-4 (S态)**: Linux/StarryOS

## 系统架构

**JH7110非对称多处理器配置**：
- **hart0**: embassy_preempt独占M态（无OpenSBI层）
- **hart1-4**: 标准配置（OpenSBI M态 + Linux S态）

## IPI通信机制

### 场景1: Linux → OpenSBI → embassy_preempt

```mermaid
sequenceDiagram
    participant Linux as Linux (S态)
    participant OpenSBI as OpenSBI (M态)
    participant CLINT as CLINT
    participant RTOS as embassy_preempt (M态)
    participant Shm as 共享内存

    Note over Linux,RTOS: Linux发送消息给embassy_preempt

    Linux->>Shm: 1. 写入消息到Linux→RTOS队列
    Linux->>Shm: 2. 更新write_idx
    Linux->>Shm: 3. 内存屏障(release)

    Linux->>OpenSBI: 4. SBI ecall(SBI_EXT_RTOS_IPI)<br/>sbi_ecall(extension, func, ...)
    OpenSBI->>OpenSBI: 5. 验证参数(target_hart==0)

    OpenSBI->>CLINT: 6. 写入MSIP0 = 1<br/>*((volatile u32*)(0x02000000)) = 1

    CLINT->>RTOS: 7. 触发hart0的MSI中断<br/>(mcause=3, Machine Software Interrupt)

    RTOS->>RTOS: 8. MSI中断处理函数被调用<br/>machine_soft()

    RTOS->>CLINT: 9. 清除MSIP0<br/>*((volatile u32*)(0x02000000)) = 0

    RTOS->>Shm: 10. 读取read_idx
    RTOS->>Shm: 11. 读取write_idx (acquire屏障)
    RTOS->>Shm: 12. 检查是否有新消息

    loop 处理所有待处理消息
        RTOS->>Shm: 13. 读取消息buffer[idx]
        RTOS->>RTOS: 14. 处理消息<br/>(GPIO/SPI/Timer等)
        RTOS->>Shm: 15. 更新read_idx
        RTOS->>Shm: 16. 更新received计数
    end

    OpenSBI-->>Linux: 17. 返回SBI_SUCCESS
    Note over RTOS: embassy_preempt继续执行<br/>消息处理完成
```

### 场景2: embassy_preempt → Linux（完整流程）

```mermaid
sequenceDiagram
    participant RTOS as embassy_preempt (M态)
    participant Shm as 共享内存
    participant CLINT as CLINT
    participant OpenSBI as OpenSBI (hart1, M态)
    participant Linux as Linux (hart1, S态)

    Note over RTOS,Linux: embassy_preempt发送消息给Linux

    RTOS->>Shm: 1. 写入消息到RTOS→Linux队列
    RTOS->>Shm: 2. 更新write_idx
    RTOS->>Shm: 3. 内存屏障(release)

    RTOS->>CLINT: 4. 写入MSIP1 = 1<br/>writel(1, 0x02000004)

    Note over CLINT: 触发hart1的MSI中断<br/>(mcause=3)

    CLINT->>OpenSBI: 5. sbi_trap_handler()<br/>捕获MSI中断

    OpenSBI->>OpenSBI: 6. sbi_ipi_process()
    OpenSBI->>OpenSBI: 7. 检查ipi_data[1]->ipi_type

    Note over OpenSBI: 检测到来自hart0的IPI

    OpenSBI->>CLINT: 8. 清除MSIP1<br/>writel(0, 0x02000004)

    Note over OpenSBI: **设置MIP.SSIP**

    OpenSBI->>OpenSBI: 9. csr_set(CSR_MIP, MIP_SSIP)

    OpenSBI->>Linux: 10. mret返回<br/>触发SSI中断(scause=1)

    Note over Linux: do_irq() → handle_IPI()

    Linux->>Shm: 11. 读取read_idx
    Linux->>Shm: 12. 读取write_idx (acquire屏障)

    loop 处理所有待处理消息
        Linux->>Shm: 13. 读取消息buffer[idx]
        Linux->>Linux: 14. 处理消息
        Linux->>Shm: 15. 更新read_idx
    end

    Linux->>Linux: 16. sret返回

    Note over RTOS,Linux: embassy_preempt继续执行<br/>不需要等待Linux响应
```

## 共享内存设计

### 内存布局

```

┌────────────────────────────────────────┐
│  magic number和版本 (16 bytes)         │
├────────────────────────────────────────┤
│  Linux → RTOS 消息队列 (8KB)           │
│  - 环形缓冲区                           │
│  - 读/写索引                           │
│  - 消息计数                            │
├────────────────────────────────────────┤
│  RTOS → Linux 消息队列 (8KB)           │
│  - 环形缓冲区                           │
│  - 读/写索引                           │
│  - 消息计数                            │
├────────────────────────────────────────┤
│  同步和状态区域 (8KB)                  │
│  - 原子标志位                           │
│  - 心跳计数器                          │
│  - 错误状态                            │
├────────────────────────────────────────┤
│  大数据传输区 (40KB)                   │
│  - 用于传递大数据块                     │
└────────────────────────────────────────┘
```

### 消息队列结构

```rust
#[repr(C)]
struct SharedMessageQueue {
    // 魔数用于验证共享内存初始化
    magic: AtomicU32,        // 0xDEADBEEF
    version: AtomicU32,      // 版本号

    // Linux → RTOS 队列
    linux_to_rtos: MessageQueue,

    // RTOS → Linux 队列
    rtos_to_linux: MessageQueue,

    // 同步原语
    sync: SyncFlags,
}

#[repr(C)]
struct MessageQueue {
    // 环形缓冲区
    buffer: [Message; 256],  // 每个消息32字节

    // 读写索引
    read_idx: AtomicU16,
    write_idx: AtomicU16,

    // 消息计数
    count: AtomicU16,

    // 统计信息
    sent: AtomicU64,      // 发送消息总数
    received: AtomicU64,  // 接收消息总数
    dropped: AtomicU64,   // 丢弃消息数
}

#[repr(C)]
struct Message {
    msg_type: u32,        // 消息类型
    length: u32,          // 数据长度
    timestamp: u64,       // 时间戳
    data: [u8; 16],       // 小数据内联
}

#[repr(C)]
struct SyncFlags {
    // IPI触发标志
    linux_pending: AtomicBool,   // Linux有待处理消息
    rtos_pending: AtomicBool,    // RTOS有待处理消息

    // 心跳
    linux_heartbeat: AtomicU64,
    rtos_heartbeat: AtomicU64,

    // 状态
    linux_ready: AtomicBool,
    rtos_ready: AtomicBool,

    // 错误计数
    linux_errors: AtomicU32,
    rtos_errors: AtomicU32,
}
```
