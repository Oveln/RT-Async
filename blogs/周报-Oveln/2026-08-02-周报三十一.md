# 第三十一周：StarryOS AIA 中断驱动集成与 K3 COM260 板级支持（UFS/小车调试）

## 一、本周完成事项

### 1. StarryOS（tgoskits）`feat/riscv-aia` 分支：AIA 相关驱动开发

完成 RISC-V 高级中断架构（AIA）驱动从调研到可用，QEMU 与 K3 测试均通过，可正常使用。相关提交：

- `fcca4fc47` **集成 IMSIC + APLIC 驱动**，修复 virtio INTx 中断风暴
- `da4df1dcf` `irq_set_affinity` 支持 APLIC/IMSIC domain
- `a0c240578` APLIC trigger 改为从 FDT 提取 + fallback LevelHigh，修复 virtio-blk INTx 不触发
- `062027bf9` APLIC `stopei` 读后必须写回清 pending，否则 IRQ 永不清除、反复 trap
- `56cd7e15d` 代码质量订正：删死代码 + 提取纯函数 + 补单测

### 2. UFS 驱动完善（`feat/k3-board-support` 分支）

- **修复 UFS 只能跑低速的问题**：先前 UFS 驱动测试发现只能运行在低速状态，本周定位并修复，当前可跑在**最高速度**；
- 修复 transfer timeout 后 doorbell slot 卡死问题（`5285f9136`，可恢复 wedged slot）；
- 本周另有约 600 行 UFS 增量改动（`init.rs`/`regs.rs`/`mod.rs`）待整理提交，方向为传输路径与寄存器语义梳理。
