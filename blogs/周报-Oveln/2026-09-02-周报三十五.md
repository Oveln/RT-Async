# 第三十五周：机器人控制板上首验——R_UART0 硬件特性定案，软串口 IRQ 假设证伪

## 一、本周完成

**R_UART0 串口双向贯通（机器人通道第一步）**

- 真板 RPC 链路（robot-ctrl 固件 + rtsh）验证：`uwrite 0 48656C6C6F`（Hello）经 USB
  串口在 pin29 正确收到；USB 串口发 `1234` 到 pin32，`uread 0 4` 读回 `31323334`。
  驱动、pinmux、波特率、共口线物理通路全通。
- 期间排障：pin29 用逻辑分析仪测不到波形、USB 串口"只插 GND+RX 乱码、插上 TX 才
  正常"、短接回环读不到数据（USB 线未拔时两路输出推拉冲突，拔线后正常）。

**R_UART0 硬件特性定案（原理图 k3-com260_kit_v02 实查 + esos 官方源码仲裁）**

- 链路：pad GPIO_122/123（1.8V 域，m0 = MMC2_DAT[3]/[2]）→ BTRD04A02 四通道双向
  电平转换器 → 40pin pin29（GPIO01_LS）/pin32（GPIO07_LS）；**与 M.2 KEY-E 槽
  SDIO DATA0-3、SODIMM 跨页共网**。
- 3.3V 侧无独立上拉（上拉在 pad 内部 1.8V 侧，过转换器为弱/高阻）：网络悬空时
  浮空/低，**必须对端推挽驱动（USB TX）才有确定空闲高**——这解释了 LA 直线、
  "插 TX 才正常"、以及六月那轮"输入乱码随芯片而变"的电气根源。真机场景（对端
  设备自带驱动）不受影响。
- **mux 档位勘误**：主仓 DTS（GPIO_122/123 + MUX_MODE4）与 esos 官方 com260_ifx
  板级 `k3-pinctrl.dtsi` 的 ruart0_3_cfg **逐字节一致**，esos 官方固件同板输出正常
  ——m4 是正确档位，此前"m3 才是 R.UART0"的旧结论作废（原理图标列表序与 mux
  值存在偏移）。软串口 GPIO_113 的 MUX_MODE2 由板测（pin40 拉低）实证正确。
- 载板 V2.0 勘误"UART0 TX/RX 调换"系 X100 调试口修订，与 R.UART0 无关。
- **注意**：pin29/pin32 与 M.2 KEY-E 槽共网，槽内不得插 WiFi/BT 卡（会驱动
  SDIO 线，与底盘通信冲突）。

**软串口（pin40）IRQ=9 假设证伪（系统性实锤）**

- `arm 0 150` 后 pin40 全程低电平：probe 空闲高（psr 置位）→ kick 拉低 start 位
  → **ISR 从不触发**（TIMER_IRQ=9 不对）→ 线停死低。
- 连带症状：帧内 mask 的 mailbox（单源 69）永不恢复 → 之后所有 RPC 无响应、
  rtsh 假死——**同一根因的旁证**。
- 候选固件已产出：`esos-irq8.itb`（先测）/ `esos-irq10.itb`（后测），默认
  esos.itb = irq8。若两者均不响，下一步对照手册 int_src 表反查。

**硬件处置（可选）**

- 无设备测量/调试场景：pin29、pin32 各加 10kΩ 上拉到 pin1（VDD_3V3_SYS），
  恢复 UART 空闲高电平（亦 SDIO 总线标准上拉），LA/USB 均不依赖"先插 TX"；
  RX 浮动噪声亦消除。真机场景无需加。
